# Нативный доступ к микрофону и гарантированный ввод

## Что будет сделано

- Подключить Capacitor к существующему приложению с идентификатором `app.lovable.c2a084d814ba40afa44202793b9e97fc` и именем `hebrew-buddy-pro`.
- Создать Android-проект и добавить разрешения `RECORD_AUDIO` и `MODIFY_AUDIO_SETTINGS` в манифест.
- Настроить Android WebView на обработку запросов аудиозахвата. Разрешать только микрофон и только после системного runtime-разрешения пользователя; не выдавать странице доступ ко всем запрошенным ресурсам.
- Улучшить окно помощника: при касании текстового поля сразу фокусировать его и открывать Android-клавиатуру, чтобы пользователь мог использовать микрофон Gboard/Google Voice Typing.
- Показывать под полем постоянное понятное состояние Web Speech API: запись, отсутствие поддержки или точный код ошибки (`not-allowed`, `no-speech`, `audio-capture` и т. п.).
- Проверить веб-сборку и Android-синхронизацию.

## Технические детали

- Capacitor будет использовать URL мобильного предпросмотра для горячей перезагрузки.
- Нативный обработчик не сможет гарантировать работу Web Speech API, если конкретная версия Android System WebView не реализует распознавание речи. Поэтому клавиатурная диктовка остаётся гарантированным резервным способом.
- После получения проекта из GitHub потребуется выполнить `npm install`, затем `npx cap sync`; запуск — через Android Studio или `npx cap run android`.
